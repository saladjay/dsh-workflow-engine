# Rust 独立服务作为执行数据面

企业版 dsh 基于 Node/V8（单线程），无法满足并行工作流与多用户多工作流并发的执行需求。决定将执行底层重构为独立的 Rust 服务（Tokio 多线程），dsh 仅保留控制面职责（工作流定义、画布、触发、权限、查询），通过内部 API 调用执行引擎。

## Considered Options

- NAPI 内嵌 Rust：与 V8 生命周期/事件循环耦合，重负载互相干扰 → 否决
- Go 独立服务：可行，但候选依赖生态（rig/swiftide/graphbit）与团队既有调研集中在 Rust → 否决
- 纯 Node 重构（worker_threads/cluster）：治标不治本，隔离与调度能力弱 → 否决

## Consequences

- 引擎可独立水平扩展与部署升级；崩溃隔离在进程级
- 控制面/数据面需要内部鉴权与服务发现（后续 ADR）

## 修订

- 2026-11-26：「引擎可独立水平扩展」本期不成立——只支持单实例部署；多实例前需单独设计 SSE 扇出、唤醒/取消路由与接管租约（grill Round 5 U11②）。
