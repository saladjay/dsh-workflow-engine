# 执行配置单一存储于引擎库

凡引擎执行时要用到的配置——工作流定义与版本、Node Binding、Capability、Provider 配置、密钥库（local 档）、会话变量——只存引擎库，控制面通过引擎的管理 API 读写。控制面库只保留自己的业务元数据（权限、目录、触发器日程）。理由：导入校验、发布校验、执行都在引擎，配置若有两个家就必然漂移；控制面作为唯一来源、按调用下发则让版本引用和导入期校验无处安放。

## Considered Options

- 控制面为源，每次调用随请求下发定义与绑定，引擎不存配置：引擎更无状态，但版本引用、导入期校验、挂起数天后的恢复都需要定义在引擎侧稳定存在 → 否决
- 两边都存：双写必然漂移 → 否决

## Consequences

- 控制面是这些配置的写入口（界面与权限在控制面），但不是存储方；引擎管理 API 只对控制面开放
- ADR-0009 中「绑定关系存控制面配置」的表述作废
