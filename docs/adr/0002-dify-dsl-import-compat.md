# Dify DSL 级导入兼容（单向）

存量 Dify 企业客户的工作流迁移是真实需求，决定以"原样导入 Dify 导出的 .yml 并正确执行"为兼容目标，含 `{{#node.var#}}` 变量语法到内部变量引用的映射。明确**不做反向导出**：自有扩展节点（如 Capability 类节点、ask-user 类节点）无法在 Dify DSL 中表达。

## Consequences

- 不支持节点的导入策略必须定义（占位导入 vs 整单拒绝），见 grill 记录 R4
- Dify 各节点的执行语义是兼容性契约的一部分，节点级错误处理语义需对齐（见 R9）

## 修订

- 2026-11-26：版本策略由「仅收 0.7.0」改为「接受版本区间 + 导入期归一化」，只拒绝高于支持上限的文件（grill Round 5 U8）。
- 2026-11-26：「自有扩展节点无法在 Dify DSL 中表达」这条理由不再成立——自有节点放在 Dify DSL 结构之上的扩展命名空间里（ADR-0010）；「不承诺反向导出」的结论保留。
- 2026-11-26：版本区间下限定为 0.1.5；比 0.7.0 新的文件不再拒绝，改为带警告导入——版本号和内容不可靠地对应，真正的把关是按节点类型逐个校验（grill Round 8 X1）。导入接口同时接受 `.ifpkg`。
