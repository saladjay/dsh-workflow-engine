# 密钥占位符 `{{secret.name}}` 与统一出口（网关 / 本地）

密钥在配置里只有一种写法：`{{secret.name}}` 占位符。占位符只在引擎的出口层被替换成真实值，工作流与 Capability 的配置、节点逻辑都不接触明文。出口层按部署档位二选一：`gateway` 档（企业默认）把占位符原样转发给企业网关，由网关在出网时替换；`local` 档（无网关环境，如本地开发、POC）由引擎用自己的密钥库替换，并自行做 SSRF 校验。替换失败（该 secret 未配置）时拒绝请求并回传错误，防止占位符原样泄漏。

## Considered Options

- 「静态密钥 AES-GCM 落库」与「网关占位符」两种模式并存、按 Capability 各选其一：在出站流量都过网关的前提下，静态模式是多余的第二套实现，也让「引擎是否持有密钥」没有唯一答案 → 否决，改为按部署档位选择
- 本机 stdio 方式的 MCP：要在引擎宿主机起进程、密钥走环境变量，绕开出口层 → 本期不支持；MCP 只接远程传输（Streamable HTTP / SSE），同样走出口层

## Consequences

- 语法上 `{{secret.name}}` 与变量模板 `{{#node.var#}}` 使用不同定界符（无井号），解析器互不干扰
- `gateway` 档下引擎零密钥，出网流量全部过网关，直连外部地址的路径关闭；`local` 档下引擎持有密钥库（AES-GCM 加密落库）
- 占位符能否出现在请求 body 里取决于网关的替换能力，待确认（docs/open-issues.md OI-001）
