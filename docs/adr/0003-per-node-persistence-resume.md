# 每节点落库与断点续跑

为支持暂停/恢复（ask-user 类节点的等待输入/审批）、取消与进程重启后续跑，决定每个节点完成即将其输出与变量快照落库（轻量事件溯源），Invocation 的挂起与恢复均以持久化快照为依据，而非依赖进程内存。首个仓储实现为 MySQL，仓储接口抽象化以便替换/增加 PostgreSQL。

## Consequences

- 运行记录表写入频率高（每节点至少一条），需要考虑批量与索引设计
- "等待用户输入"成为可持久化状态，唤醒事件在重启后依然有效

## 修订

- 2026-11-26：补上在途节点的语义——重启后至少一次重跑，幂等键随节点执行标识下发；节点开始前先落库（ADR-0011、ADR-0012）。
