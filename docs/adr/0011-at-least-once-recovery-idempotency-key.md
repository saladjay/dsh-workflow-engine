# 重启续跑采用至少一次，幂等键随节点执行下发

进程在节点执行途中被杀时，该节点可能已经产生副作用而输出尚未落库。决定重启后把在途节点重跑（至少一次），而不是置为未知等待人工裁决：每次节点执行（Node Run）有跨重启稳定的标识，重跑沿用同一标识，引擎把它作为幂等键带在 HTTP 出站请求上，后端可据此去重。契约写明：崩溃恢复时节点可能执行不止一次。在途策略做成配置项（重跑 / 挂起待裁决 / 按节点标注），本期只实现「重跑」。

## Considered Options

- 在途节点置为「未知」并挂起，等人工裁决：对资金类流程更安全，但需要裁决界面和运维流程，本期没有这类流程 → 配置项预留，不实现
- 追求恰好一次：需要节点与外部系统共同参与两阶段提交，成本与收益不成比例 → 否决

## Consequences

- 重启时处于运行中的 Invocation 自动续跑；流式 LLM 调用被中断的部分无法计入 token 统计
- 检测「在途」依赖节点开始前的落库记录，所以节点开始事件必须先落库再执行（ADR-0012）
