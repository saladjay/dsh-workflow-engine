### 一、没定的设计问题

#### OI-003 文档服务用什么语言实现

- 状态：open（第 9 轮的 Y4，用户答「待定」，倾向 Python 服务先做、以后换 C# 服务）
- 已定的部分：D64，文档服务是独立的 HTTP 服务，经 Capability 接入；D66，本期支持模板填充、从零生成、编辑既有文件。
- 事实（`office libs.md`）：D64 之后「Rust 调 C#」不再是问题，要定的是这个服务用什么写。Rust 的库在 docx 的模板填充和 pptx 上最弱；C# 的免费库偏底层，能力最全的是商业套件；Python 有现成的高层库，本机已经装着。
- 待定：C# 服务、Python 服务、Rust 服务之间怎么选。推荐 Python 先做，C# 留作升级路线。取决于一件我不知道的事：有没有现成的 C# 文档服务，或者有没有 C# 的人手。

#### OI-004 工作流的 token 账要不要并入 dsh 的会话归属账

- 状态：open（本期不做）
- 已定的部分：D70，引擎先单独记账。
- 背景：dsh 的会话级 token 归属（内核的投影加一个写 MySQL 汇总表的插件）已经设计、没有实施，按工具、会话自身、压缩、skill 四类记账。工作流内部的消耗不在其中。
- 两本账的口径不同：dsh 分未缓存输入、缓存写、缓存读、输出、推理；引擎的 `token_usage` 是 prompt、completion、total，另存厂商的原始用量。要对账的时候从 `raw_usage` 里取。
- 待办：dsh 的汇总表插件实施时再议。

#### OI-001 网关能否替换 body 里的密钥占位符

- 状态：open（待补充）
- 来源：grill Round 5 U9 ②（2026-11-26）
- 问题：企业出口网关现在能否替换 HTTP 请求 **body** 中的 `{{secret.name}}`？JSON、multipart、流式三种 body 需分别确认。
